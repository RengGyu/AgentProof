# AgentProof의 일반화 가능한 요구사항 검증·평가 설계

## 결론

가장 타당한 방향은 기존 검증기를 폐기하는 것이 아니라, **목표 추출의 표현과 평가 계약을 먼저 바로잡고, 기존의 결정적 증거 검증에 연결하는 것**이다. 핵심 질문은 “이 문장이 요구사항인가, 구현 주장인가?”가 아니라 “이 PR이 이루려는 목표를 담고 있는가, 누구의 주장인가, 무엇으로 확인할 수 있는가?”다. 목표와 구현 주장은 함께 존재할 수 있지만, 주장이 곧 구현 증거가 되지는 않는다.

추천 순서는 **평가 계약 고정 → 출처가 연결된 목표·주장 분리 → 의미 보존·범위 시험 → 미사용 데이터 비교 → 실제 리뷰 효용 평가**다. 세밀한 역할 분류 정확도 하나로 제품 성능을 대표시키지 않는다. 아래 설계는 연구에 근거한 적용 제안이며, AgentProof에서 성능 개선이 입증된 구현이나 승인된 새 채택 기준은 아니다.

| 원인 | 추천 해결 방법 | 해결 여부를 확인하는 기준 |
|---|---|---|
| 목표와 구현 주장을 배타적으로 분류 | 목표 포함 여부와 발화 역할을 별도로 기록 | 구현형 표현의 명시적 목표는 보존하고, 목표 없는 구현 설명은 승격하지 않음 |
| 문단 출력과 문장 라벨의 단위 불일치 | 원문에 연결된 최소한의 완결된 명제, 조건·부정 보존 | 분해 누락·추가·조건 손실 및 합치기/나누기 시험 |
| AI 라벨과 해석 변경에 따른 점수 변동 | 제품 정의에 맞춘 사람 라벨, 버전·평가 방법 사전 동결 | 같은 기준으로 기존/후보 모두 평가; 모호성과 변경 이력 공개 |
| 긴 본문·반복 문장이 점수를 지배 | 출현 위치와 고유 목표를 구분하고 PR·그룹별 집계 | 중복 불변성, 목표 단위 precision/recall, 무목표 PR의 잡음 |
| 후보 필터·예산에 의한 조기 누락 | 모든 원문 단위의 처리 상태를 남기고 의미 제외와 보안 제외 분리 | 전체 목표 대비 입력 도달률, 미검토 이유·수량 |
| 문맥을 늘리면서 절차·다른 작업까지 목표화 | 제한된 원문 문맥, 현재 PR 범위 판단, 모호할 때만 확장 | 실제 목표/절차 대조쌍, 확장 후 해결·새 오류·비용 |
| 본 사례에 맞춘 반복 수정과 작은 표본 | 저장소·fork·근접 템플릿 그룹 분리, 잠긴 평가셋 | 미사용 그룹에서도 효과가 유지되는지, 불확실성 구간 |
| 실행 변동을 기능 효과로 해석 | 동일 초기 출력 재사용 및 사전 고정된 반복 비교 | 변동과 증분 효과를 분리; 미작동 기능은 효과 미측정 |
| 역할 분류와 증거·권한 판단의 혼동 위험 | 의미·출처 권한·증거 적합성의 경계 유지 | 올바른 결론과 올바른 증거 연결을 동시에 만족 |
| 역할 점수를 제품 효용으로 해석 | 후보 품질·증거 판정·사람 리뷰 효용을 각각 평가 | 오판·누락·불필요한 확인·리뷰 시간의 동시 변화 |

## 1. 확인된 출발점과 아직 모르는 것

현재 네 PR 실험은 27개의 기존 AI 제안 라벨, 34개 원문 단위, 공백을 제외한 UTF-16 코드 단위 2,377개를 비교한다. `objective_candidate`는 requirement, `mixed_or_ambiguous`/보류는 ambiguous, 나머지 유효 역할은 non_requirement로 대응한다. 따라서 `implementation_claim` 안에 명시적 목표가 있어도 이 평가에서는 긍정이 아니다. 이는 제품이 보존하려는 대상과 평가 정의가 어긋날 수 있다는 구체적인 구조 문제다. [로컬 진단: method·inventory](/Users/jeonggyuju/Project_folder/AgentProof/.worktrees/agentproof-recovery-20260913/docs/verification/2026-09-14-role-pilot/diagnostic-audit.json)

확인된 수치는 다음처럼 제한적으로 해석해야 한다.

- 긍정 라벨 4개는 출현 위치 4개다. FastAPI 제목/본문 반복을 제외하면 동일 문자열 기준 3개이며, 이것도 의미적으로 독립적인 요구사항 3개가 확정됐다는 뜻은 아니다.
- 기존의 다른 AI 검수 라벨 버전에서는 Django 제목 55자가 긍정에 추가된다. 동일 출력의 요구사항 문자 보존율은 모든 버전에서 138/138 = 100%에서 138/193 = 71.50%로 바뀐다. 전체 일치도는 그대로다.
- Django 한 PR이 문자 분모의 1,644/2,377 = 69.16%를 차지한다. 다만 PR별 동일 가중치로 바꿔도 이번 버전 순서는 같으므로, 가중치 문제만으로 관측된 악화를 설명할 수는 없다.
- Flask의 한 문단 단위에는 서로 다른 라벨이 함께 있다. 고정된 이 분할에서 한 역할만 출력하면 원래 문장 라벨을 모두 맞출 수 없다.
- V3/V4 초기 요청은 같고 V4 추가 문맥 호출은 0회였다. 출력 차이는 별도 실행에서 발생했으며, 추가 문맥 기능의 효능을 보여주지 않는다.
- 네 PR 입력에는 수집된 원 Issue 작업 본문, 변경 파일 및 체크·로그가 없다. 이 결과는 구현 증거 판정이나 리뷰어 효용을 측정하지 않는다. ## 2. 원인별 해결 설계

### 2.1 목표와 구현 주장: 하나를 선택하지 말고 두 질문으로 분리

연구 근거: Röttger 등은 라벨링이 어떤 후속 사용을 위한 것인지 명확히 해야 한다고 설명한다. 한 제품 정책을 일관되게 적용하는 평가와 가능한 여러 해석을 조사하는 평가는 목적이 다르다. 이 논문은 PR 분류기를 직접 실험한 것이 아니라, 라벨 정의를 제품 목적에 맞춰야 한다는 방법론적 근거다. [1. Röttger 등, 2022](https://aclanthology.org/2022.naacl-main.13/)

설계 제안: 기존 출처·권한 정보를 재사용하면서, 연구용 출력에 최소한 다음 판단을 분리한다. 다음 표는 개념 설계이며 실제 JSON 필드 변경이 아니다.

| 질문 | 기록할 내용 | 판정 경계 |
|---|---|---|
| 무엇을 이루려는가? | 명시적 목표 있음 / 없음 / 미해결, 원문 위치 | 문법적 시제가 아니라 현재 PR 목표와 연결되는가 |
| 어떤 말인가? | 요청·구현 주장·실행 주장·배경·절차 등 | 목표 포함 여부와 동시에 기록 가능 |
| 누구의 말인가? | 기존 출처와 `author_claim` 등 권한 | 모델이 권한을 재분류하거나 승격하지 않음 |
| 확인할 수 있는가? | 명시 기준과 관련 증거, 확인 불가 이유 | 분류 모델이 `met`이나 구현 사실을 확정하지 않음 |

예를 들어, “이번 PR에서 빈 입력이면 400을 반환하도록 수정했다”는 **목표 있음 + 구현 주장 + 작성자 출처**로 보존한다. 실제로 400을 반환하는지는 아직 별도 문제다. 반대로 “내부 헬퍼를 정리했다”에서 명시하지 않은 외부 동작이나 성능 목표를 만들어내지 않는다. 이 예시는 설계를 설명하기 위한 합성 문장이다.

`목표 있음`을 세부 검증 기준까지 완성됐다는 뜻으로 쓰지 않는다. “불안정한 테스트를 고쳤다”는 목표 후보를 보존할 수 있지만, 허용 실패율·반복 횟수를 임의로 만들어 합격 판정을 내릴 수는 없다. 기준이 부족하면 후보를 남기고 검증 기준 불명확을 표시한다.

검증 방법: 목표 의미를 유지하면서 요청형/완료형을 바꾼 쌍에서 목표 보존은 같고 발화 역할은 달라지는지 본다. “이 PR의 목표”와 “과거 릴리스의 변경”을 바꾼 쌍에서는 현재 PR 목표 판정이 달라져야 한다. 동일 제목 아래 모든 내용을 같은 역할로 강제하는 예외 규칙은 추가하지 않는다.

### 2.2 문단·문장 불일치: 원문에 연결된 명제로 정렬하되 과분해를 막기

연구 근거: FActScore는 긴 응답을 정보 단위로 나누어 검증한다. 하지만 후속 연구는 같은 텍스트도 분해 방식에 따라 평가 점수가 달라지고, 분해 단계의 오류가 생성 모델의 오류처럼 계산될 수 있음을 보여준다. 따라서 “더 잘게 나누면 더 정확하다”는 결론은 성립하지 않는다. [2. Min 등, 2023](https://aclanthology.org/2023.emnlp-main.741/), [3. Wanner 등, 2024](https://aclanthology.org/2024.starsem-1.13/)

설계 제안은 두 단계다. 첫째, 기존 Markdown 구조 등록은 원문 보존에 사용한다. 둘째, 서로 독립적으로 평가할 내용만 최소한의 완결된 명제로 나누며, 모든 명제는 기존 원문 ID·해시·범위에 연결한다. 필요한 조건이나 대명사의 선행사는 별도 문맥 참조로 남긴다. 문장부호 기준 분할은 초기 경계일 뿐 의미적 정답이 아니다.

- “A인 경우 B를 해야 한다”에서 A를 떼어 무조건 B라는 목표로 바꾸지 않는다.
- 부정, 예외, 대상 버전, 수량 조건을 보존한다. 서로 대안인 조건을 모두 필요한 조건으로 바꾸지 않는다.
- 분리하면 의미가 불완전해지는 결합은 묶어 남기거나 미해결로 표시한다.
- 출처 범위가 실제 존재한다는 검사는 결정적으로 할 수 있지만, 요약이 원뜻을 보존했는지는 별도의 의미 평가가 필요하다.

평가할 것은 분해 개수가 아니라 **원래 목표의 보존, 원문에 없는 목표의 추가, 조건·부정 손실, 불필요한 중복**이다. 명제 수를 늘리는 것만으로 precision이나 recall의 분모를 유리하게 조정하지 못하게 한다. 기존 Flask 문단은 개발용 회귀 사례로만 남기고, 다른 저장소의 새로운 혼합 문단으로 동일 원리를 검사한다.

### 2.3 AI 라벨·기준 변경: 제품 계약에 맞춘 사람 라벨과 버전 고정

설계 제안: 목표 정의는 “현재 PR에서 의도된, 원문에 드러난 동작 또는 산출물”로 정리한다. 구현 완료형으로 쓰였다는 이유로 제외하지 않고, 단순 과정 보고를 새 목표로 추론하지 않는다. 목표/구현 역할의 동시 성립은 모호성이 아니라 두 축이 모두 참인 경우다. 실제로 현재 PR 범위인지 해석이 갈리는 경우만 미해결로 남긴다.

사람 라벨은 다음 절차로 만든다.

1. 작은 별도 연습 자료로 목표 정의·범위·원문 단위·중복·조건의 기준을 정리한다. 이 자료는 평가셋이 아니다.
2. 이후 두 사람이 AI 라벨과 시스템 출력을 보지 않고 전체 원문을 독립 판독한다. 목표 라벨링 단계에서는 diff/CI를 보지 않는다.
3. 불일치를 경계 차이, 목표 범위, 표현 해석, 실제 실수로 구분한다. 조정한 이유와 원래 두 라벨을 보존한다.
4. 해결되지 않은 항목은 허용 해석 집합과 이유를 남긴다. 조용히 삭제하거나 다수결로 무조건 확정하지 않는다.
5. 기준 버전·원문 해시·라벨 해시·매칭 방식·분모·분할을 출력 전에 동결한다.

이는 제품 기준을 명시적으로 적용하는 주석 설계다. 두 명의 일치율이 높다고 객관적 진실이나 모집단 대표성이 보장되지는 않는다. 모호한 사례는 명확한 사례 점수와 분리해서 결과 범위와 검토 부담을 보고한다. 허용 라벨 중 하나와 일치한다는 이유만으로 확정적 정확도에 합산하지 않는다. [1. Röttger 등, 2022](https://aclanthology.org/2022.naacl-main.13/)

기준 변경 자체를 금지할 필요는 없다. 다만 바꿨으면 **새 평가 버전**이다. 원래 점수는 보존하고, 같은 새 기준으로 기존 방식과 후보를 모두 평가한다. 구형 출력에 없는 목표 해석을 평가용 LLM이 사후에 생성해서 구형 시스템의 성능처럼 계산하지 않는다. 기존 산출물로 산출할 수 없는 지표는 측정 불가로 남긴다.

### 2.4 문자 가중·중복: 출현 위치와 평가할 목표를 분리

설계 제안: 두 종류의 식별자를 구분한다. 원문 출현 ID는 제목·본문의 모든 위치를 보존한다. PR 내부 목표 ID는 같은 목표를 가리키는 출현을 연결한다. 문자열 완전 일치는 중복 후보를 찾는 결정적 신호지만, 동일 의미 여부의 완전한 판정은 아니다.

같은 목표가 제목과 본문에 반복되면 고유 목표 보존 점수는 한 번만 준다. 서로 다른 조건·버전·권한의 진술이나 모순되는 진술은 단순 병합하지 않는다. 저장소를 가로지르는 거대한 의미 클러스터나 새 임베딩 시스템부터 만들 필요는 없다. 소규모 사람 평가셋에서 PR 내부 동일성부터 명시하면 된다.

사람이 동결한 고유 목표 집합과 시스템 후보를 의미·조건·출처 기준으로 대응시킨다. 동일 목표에 복수 후보가 대응하더라도 recall 성공을 중복 계산하지 않고, 중복 카드 수를 별도로 기록한다. 긴 문단 전체를 선택했다는 사실만으로 그 안의 모든 개별 목표를 정확히 추출했다고 인정하지 않는다. 원문 범위 겹침은 출처·입력 보존 지표이며 의미적 정확도와 다르다.

문자 가중 일치도는 버리지 않고 분할·회귀 진단용으로 유지한다. 제품 비교의 주된 요약은 목표 단위 precision/recall, PR별 결과, 저장소·템플릿 그룹별 결과로 바꾼다. 목표가 없는 PR은 recall이 정의되지 않으므로 100%로 넣지 않고, 후보 잡음 수와 불필요한 검토 시간을 따로 보고한다.

한 문서의 문자들을 독립 표본으로 간주해 불확실성 구간을 좁히지 않는다. NLP 평가에서 문장들이 같은 문서나 작성자를 공유하는 의존성은 통계적 검정의 중요한 한계로 지적된다. [12. Dror 등, 2018](https://aclanthology.org/P18-1128/)

### 2.5 조기 후보 누락: 의미 필터와 처리 예산을 별도 계측

모델이 보지 못한 목표는 그 모델의 분류 능력으로 복구할 수 없다. 후보 밖에서 복구하는 경로가 없다면, 같은 목표 정의 아래 최종 recall은 입력 도달 recall보다 높을 수 없다. 이는 이 파이프라인 구조에서 나오는 상한이며 특정 논문의 성능 예측이 아니다.

설계 제안: 원문 등록 단계에서 내용을 보존하고, 각 단위가 선택됨/판정됨/보류됨/미검토/무효 중 어디에 있는지 기록한다. 기존 ledger를 우선 재사용한다. 제목·표현 때문에 제외하는 의미 필터는 실험 변수로 두고, privacy·권한·원문 참조 검사와 분리한다.

“모든 원문 등록”은 모든 내용을 외부 모델로 전송한다는 뜻이 아니다. 개인정보 제거, 전송 허용 범위, 요청 크기·총 호출 예산은 유지한다. 안전·정책 제한으로 다룰 수 없는 단위도 없음이나 배경으로 둔갑시키지 않는다. 예산 확대 효과와 의미 필터 해제 효과는 같은 효과로 섞지 않는다.

원인 분리는 세 지표로 한다. 전체 사람 목표 중 입력까지 도달한 비율, 입력된 명확한 목표의 조건부 추출 성능, 전체 원문 대비 최종 추출 성능이다. 첫 지표가 낮으면 후보 선택 문제이고, 첫 지표는 높은데 뒤의 지표가 낮으면 표현·문맥·분류 문제를 우선 조사한다. 입력을 늘려 누락을 줄였다면 그 비용과 새 잡음도 함께 공개한다.

### 2.6 범위·문맥 오류: 구조적 이웃과 선택적 보류, 의미 대조 시험

연구 근거: 긴 문맥이 항상 안정적으로 활용되는 것은 아니며, 관련 정보의 위치를 바꿀 때 성능이 달라지는 사례가 보고됐다. 이는 제한된 문맥과 위치 시험의 근거이지, 이번 짧은 PR 실험의 악화 원인을 확정하는 근거는 아니다. 선택적 분류 연구는 확정한 영역의 오류와 전체 처리 비율을 함께 다룬다. [9. Liu 등, 2024](https://aclanthology.org/2024.tacl-1.9/), [8. Geifman·El-Yaniv, 2019](https://proceedings.mlr.press/v97/geifman19a.html)

설계 제안: 해당 명제와 상위 제목, 의미상 필요한 같은 원문의 이웃을 기본 문맥으로 둔다. 현재 PR 목표인지 판단이 안 되는 항목만 동일 섹션까지 한 번 확장하는 정책을 비교한다. 해결되지 않으면 보류한다. 목표를 해석하는 단계에 구현 diff·CI를 넣어 코드에서 목표를 역으로 만들어내지 않는다.

`Tests`, `Validation`, 체크박스, 과거형을 곧바로 비목표로 처리하지 않는다. “회귀 테스트를 추가한다”는 명시적 산출물이 될 수 있다. 반대로 일반 기여 절차나 다른 PR에 대한 제안이 현재 PR의 산출물인지는 별도 범위 문제다. 조건부 산출물은 적용 조건을 유지하며, 조건이 미확정이면 그 불확실성을 표현한다.

모델의 자체 신뢰도나 “모르면 보류”라는 문구만으로 보류 정책이 검증되지는 않는다. 같은 자동 판정 coverage에서 오류율을 비교하고, 모호한 사례가 어디로 갔는지와 사람에게 넘어가는 분량을 공개한다. 이산적인 정책 몇 개만 비교할 수 있다면 실제 관측한 점만 제시하고, 임의로 연속적인 risk–coverage 곡선을 만들어내지 않는다.

### 2.7 반복 수정·작은 표본: 개발셋, 잠긴 평가셋, 행동 시험의 역할 분리

연구 근거: 모델 자체의 학습뿐 아니라 유한한 평가 표본에서 최선의 설정을 반복 선택하는 과정도 과적합될 수 있다. 그룹이 서로 의존하면 단순 무작위 분할로 충분하지 않다. 실제 분포 변화에 맞춘 벤치마크는 새 환경에서의 성능 저하를 따로 측정한다. [4. Cawley·Talbot, 2010](https://www.jmlr.org/papers/v11/cawley10a.html), [5. scikit-learn 공식 문서](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data), [11. Koh 등, 2021](https://proceedings.mlr.press/v139/koh21a.html)

설계 제안은 세 자료의 용도를 고정하는 것이다.

- **개발·회귀 자료:** 이미 살펴본 60개와 네 PR. 원인 진단과 재발 방지에 사용하며 다시 미사용 평가셋이라 부르지 않는다.
- **자연 발생 평가 자료:** 새로운 저장소·fork 계열·실질적 본문 템플릿 그룹을 분리한다. 기존 자료와 근접 중복을 검사하고, 공통 제목 몇 개만으로 동일 템플릿이라 단정하지 않는다.
- **행동 시험 자료:** 표현을 바꿔도 유지돼야 하는 판단과 의미가 바뀌면 달라져야 하는 판단을 테스트한다. 자연 발생 PR의 실제 오류율을 추정하는 자료로 합산하지 않는다.

앞서 검토된 새 PR 36개를 조정 12개/평가 24개로 나누는 규모는 방향 결정용 시작안으로 사용할 수 있다. 독립 그룹을 우선하므로 정확한 12/24 숫자를 맞추기 위해 같은 그룹을 양쪽으로 나누지 않는다. 그룹 수·긍정 목표 수·증거 유형을 먼저 확인하고 충분하지 않으면 범위를 좁히거나 새 승인 범위에서 자료를 늘린다. PR 24개라는 숫자가 정밀도 95%나 일반화를 인증하지 않는다.

규칙·프롬프트·보류 정책은 조정 자료에서 선택하고, 후보 하나와 동결된 기준 방식만 잠긴 평가 자료에서 비교한다. 결과를 본 뒤 수정했다면 그 자료는 이후 개발 자료가 된다. 여기서 미사용은 AgentProof 개발 미사용을 뜻하며 모델의 사전학습 미노출을 보장하지 않는다.

### 2.8 실행 변동: 기능 비교와 재실행 흔들림 분리

현재 V4처럼 실제 확장이 0번이면 확장의 효능은 미측정이다. 호출 제한 안에서 정상 종료했음을 확인한 것과 의미적 개선을 확인한 것은 다르다.

설계 제안: 확장 정책만 비교할 때는 **같은 초기 판정 결과를 복제한 상태**에서 한쪽만 확장한다. 그래야 초기 생성이 달라진 효과를 확장 효과로 계산하지 않는다. 캐시된 원문·판정은 승인된 보관 경계 안에서만 재사용하며, 물리적으로 실행한 호출 비용과 각 정책에 귀속하는 비용을 구분한다.

별도로 선택된 두 방식에 대해 동일 모델·입력·예산을 고정하고 사전에 정한 반복 수로 비교한다. 작은 반복은 흔들림을 탐지하는 자료이지 안정성을 인증하는 자료는 아니다. 실행 순서도 한 버전이 항상 먼저 오지 않도록 미리 균형화한다. 요청 해시·관측 모델·유효성·확장 수·토큰·지연·실패는 기존 journal 구조를 재사용한다.

자료가 충분해지면 동일 PR의 두 결과를 묶어 비교하고, PR들이 같은 그룹에 속하면 그 그룹 단위의 의존성을 보존한 불확실성 분석을 한다. 네 PR의 수천 문자를 수천 번의 독립 관측처럼 취급하지 않는다. 작은 표본에서 재표본화만 많이 한다고 정보가 늘어나지 않는다. [12. Dror 등, 2018](https://aclanthology.org/P18-1128/)

### 2.9 권한·증거 혼동: 목표를 보존해도 완료 판정은 별도 계약으로

연구 근거: FEVER는 판정 라벨뿐 아니라 그 판정을 정당화하는 증거도 요구한다. 올바른 라벨이더라도 적절한 증거를 반환하지 않으면 증거를 요구하는 범주에서 정답으로 인정하지 않는다. 이를 AgentProof에 적용하는 것은 설계 추론이며, 자연어 사실 검증을 소프트웨어 구현 증명과 동일시하는 것은 아니다. [10. Thorne 등, 2018](https://aclanthology.org/N18-1074/)

AgentProof는 원문 목표, 출처 권한, 기준에 맞는 증거의 연결을 유지해야 한다. 현재 코드에도 출처 권한과 exact-head 아티팩트 기준의 결과를 결합하는 경로가 있으므로, 연구용 역할 분류기가 이를 대체하거나 새 완료 권한을 갖게 할 이유가 없다. [기존 ordinary requirement 판정 경로](/Users/jeonggyuju/Project_folder/AgentProof/.worktrees/agentproof-recovery-20260913/src/lib/ordinary-requirement-outcomes.ts:48)

제안하는 경계는 다음과 같다.

- “원문에 이 목표가 있다”는 목표 존재에 대한 근거다. 구현됐다는 근거는 아니다.
- `author_claim` 후보에 증거가 연결되더라도 출처 자체가 authoritative로 바뀌지는 않는다. 보고서에서도 둘을 구별한다.
- 관련 파일이 바뀌었다는 사실은 변경 증거이지 원하는 동작의 충족 증거가 아니다. 체크 성공도 실행된 검사 범위에 한정된다.
- 수집된 적절한 증거가 없다는 것과 실패 증거가 있다는 것을 구분한다. 지원되지 않는 기준은 `unclear`/확인 불가로 남긴다.
- LLM이 찾은 기준·증거 연결은 검증할 제안이다. `met`은 해당 기준에 대한 기존의 허용된 증거·검증 계약을 충족할 때만 생성한다.

평가는 “판정만 맞음”과 “판정 + 출처 + 적합한 증거 + 대상 revision이 모두 맞음”을 별도로 측정한다. 같은 내용을 다른 출처나 이전 revision의 증거에 연결했을 때 통과하지 않는 대조 시험을 둔다. 서로 충돌하는 증거가 있으면 개수를 세어 다수결로 통과시키지 않는다.

### 2.10 제품 효용: 사람이 더 정확하게, 덜 헤매며 판단하는가

연구 근거: 인간–AI 협업 메타분석은 사람 단독 대비 개선과 사람/AI 중 더 나은 쪽 대비 개선이 서로 다른 질문이며, 효과가 과업에 따라 달라진다고 보고한다. 모델의 단독 점수가 높다는 사실만으로 사람에게 도움이 되는 도구가 되었다고 결론 내릴 수 없다. 이 연구는 AgentProof나 PR 리뷰의 효과를 직접 측정하지 않았다. [13. Vaccaro 등, 2024](https://www.nature.com/articles/s41562-024-02024-1.pdf)

설계 제안: 충분한 증거가 있는 소규모 PR 묶음에서 기본 원문·코드·CI를 보는 리뷰와 AgentProof 보고서를 함께 보는 리뷰를 비교한다. 기존 보고서가 있다면 개선 보고서와도 비교한다. 같은 사람이 같은 PR을 보고 정답을 기억한 뒤 다른 조건을 평가하지 않도록 PR/리뷰어 배정과 순서를 균형화한다. 시스템 이름은 가능한 범위에서 가리고, 최종 판단의 채점자는 조건을 모르게 한다.

주요 결과는 제대로 잡아낸 미충족 목표, 잘못된 완료 판단, 원래 없던 요구사항 때문에 생긴 불필요한 요청, 관련 증거를 찾는 시간이다. 전체 리뷰 시간·보고서 작성 지연·수동 확인량도 함께 기록한다. 보고서 없는 조건과 점검할 자료는 같아야 하며, 보고서가 단순히 더 많은 원자료를 제공한 효과와 해석 기능 효과를 구별한다.

빠르게 잘못 판단했다면 효용 개선이 아니다. 설문에서 유용하다고 느꼈다는 응답도 실제 정답률이나 시간 개선을 대체하지 않는다. 전반적 파일 품질이나 일반 코드 리뷰 점수를 붙이기보다, 선언된 목표와 수집된 증거를 바르게 대조하는 좁은 제품 임무를 측정한다.

## 3. 사례 암기를 막는 행동 시험

CheckList는 최소 기능, 의미를 보존하는 변형, 예측이 바뀌어야 하는 변형을 구분한다. Contrast Sets는 표면적 특징을 크게 바꾸지 않으면서 정답이 달라지는 사례를 만들어 결정 경계를 검사한다. 두 접근을 활용하되, 아래 시험 자체가 자연 발생 PR의 대표 표본이라는 주장은 하지 않는다. [6. Ribeiro 등, 2020](https://aclanthology.org/2020.acl-main.442/), [7. Gardner 등, 2020](https://aclanthology.org/2020.findings-emnlp.117/)

| 시험 계열 | 변경 | 기대 결과 |
|---|---|---|
| 표현 불변성 | 현재 PR의 같은 목표를 요청형 ↔ 구현 완료형으로 표현 | 목표 존재·내용 유지; 발화 역할은 달라질 수 있음 |
| 형식 불변성 | 같은 의미를 목록 ↔ 문단, 중립적 제목·순서로 표현 | 목표·권한·증거 결론 유지 |
| 반복 불변성 | 제목의 같은 목표를 본문에도 반복 | 고유 목표 점수·완료 근거 수가 부풀지 않음 |
| 범위 대조 | “이번 PR에서” ↔ “다음 PR에서” 또는 “과거 버전에서” | 현재 PR 목표 판정은 달라짐 |
| 절차/산출물 대조 | 일반 제출 절차 ↔ 이번 변경의 명시적 테스트·문서 산출물 | 위치나 키워드가 아니라 내용에 따라 구분 |
| 조건·부정 | 동일 대상을 조건부/무조건, 허용/금지로 변경 | 기준을 바꿔야 하며 조건을 누락하지 않음 |
| 혼합 명제 | 독립 목표와 배경을 합치거나 별도 문단으로 분리 | 보존된 목표는 같고 배경은 목표로 늘어나지 않음 |
| 출처·증거 대조 | 같은 목표에 작성자 말, 적합한 증거, 무관·구 revision 증거를 연결 | 의미 목표는 유지되지만 권한·확인 상태는 맞게 분리 |
| 미검토 대조 | 예산 소진·수집 실패·privacy 제한으로 일부 입력을 못 봄 | 미검토를 비목표나 성공으로 계산하지 않음 |

변형 후 의미가 유지되는지 사람이 먼저 확인해야 한다. 예를 들어 `Non-goals`로 제목을 바꾸는 것은 단순 서식 변화가 아니며, 과거형으로 바꾸면서 현재 PR 범위까지 바뀌면 목표 불변성을 요구할 수 없다. 틀린 불변성 테스트 역시 잘못된 제품 규칙이 된다.

개발용 변형과 잠긴 평가용 변형은 원본 PR과 함께 분할한다. 동일 예시의 이름만 바꾼 수백 문장을 수백 개의 독립 증거로 세지 않는다. 평가용 변형은 대상 모델의 오답을 보며 유리하게 조정하지 않는다. 기존 실패는 회귀 시험으로 남기고, 채택 판단은 새로운 자연 자료와 별도의 변형 계열에서 확인한다.

## 4. 성능을 세 층으로 분리하는 평가 계약

다음은 제안 지표이며 기존 결과의 분모를 소급 변경하는 구현이 아니다.

| 층 | 지표 | 분모·성공 조건 |
|---|---|---|
| 목표 입력 | 후보 입력 recall | 확정된 전체 고유 목표 중 필요한 목표 원문이 모델 입력까지 도달한 비율 |
| 목표 추출 | 목표 recall | 확정된 전체 고유 목표 중 의미·조건·범위가 보존된 추출 목표 수; 입력 밖 목표도 분모 유지 |
| 목표 추출 | 후보 precision | 시스템의 고유 후보 중 실제 현재 PR 목표와 대응하는 비율; 원문에 없는 목표는 실패 |
| 목표 추출 | 중복·잡음 | 중복 카드 수, 무목표 PR당 잘못된 후보 수, 원문에 없는 조건 추가 수 |
| 의미 처리 | 축별 정확도·역할 F1 | 동일 세분화 수준의 사람 라벨이 있을 때만 계산; 기존 3분류 라벨로 11역할 F1을 주장하지 않음 |
| 보류 정책 | coverage·오류·미검토 | 전체 원문/명제를 기준으로 정의된 자동 판정 비율과 그 영역 오류, 제외 사유·수량을 함께 보고 |
| 증거 판정 | 근거가 맞는 판정 비율 | 결론뿐 아니라 기준·출처·관련 증거·revision이 함께 맞아야 성공 |
| 증거 판정 | 거짓 완료·증거 누락 | 부적절한 `met` 수/전체 `met` 수, 실패/확인 불가의 오판; 분모 0이면 측정 불가 |
| 사람 효용 | 판단 품질과 부담 | 정확한 미충족 탐지, 거짓 완료, 불필요한 요청, PR당 리뷰 시간·증거 탐색 시간 |
| 운영 | 비용·지연·실패 | 실제 과금 확인값 또는 토큰, 호출·확장·재시도, PR별 p50/p95; 작은 표본 꼬리값 한계 공개 |

서로 다른 개념의 precision을 혼용하면 안 된다. 후보 precision은 잡음과 검토량에 관계하고, 완료 판정 precision은 잘못된 확신에 관계한다. 높은 recall이 필요한 후보 풀과 엄격한 완료 판정을 같은 임계값 하나로 최적화하지 않는다. 이전의 precision 95%·recall +5%p·비용 1.25배 제안은 연구가 보장한 값이 아니며, 새 평가에서 어느 층에 적용할지 먼저 명시해야 한다. 변경은 별도 승인·사전 동결 대상이다.

숫자는 분자/분모, 긍정 목표 수, PR 수, 독립 그룹 수와 함께 보고한다. 명확/모호 사례와 출처 유형을 나누고, 모호한 해석에 따른 가능한 결과 범위를 보조적으로 제시한다. 보류를 늘려 얻은 선택 영역 정확도를 전체 제품 정확도로 부르지 않는다. PR별·그룹별 평균과 전체 합산 결과를 함께 제시해 서로 다른 가중치가 대답하는 질문을 구별한다.

## 5. 가장 작은 비교 실험과 채택·중단 조건

### 5.1 비교 경로

먼저 원문/목표/권한/증거의 평가 계약을 고정한다. 기존 V0의 산출물을 가능한 공통 지표로 평가하고, 새로 추론해야만 만들 수 있는 지표는 측정 불가로 남긴다. 이후 아래 경로는 조정셋에서의 증분 실험으로 사용한다. 모든 요인의 상호작용을 규명하는 완전한 실험이라고 해석하지 않는다.

1. **대조군:** 기존 동작을 동결한다. 새 기준으로 평가한다는 이유로 기존 프롬프트·필터를 몰래 개선하지 않는다.
2. **목표 축 추가:** 같은 원문 단위·후보 선택·모델·문맥에서 목표 포함 여부와 구현 역할의 배타성만 해소한 연구 후보를 비교한다.
3. **단위 정렬:** 직전 후보에만 일반적인 명제 경계 처리를 추가하고, 경계 변경에 따른 의미 보존을 검사한다.
4. **입력 범위 비교:** 같은 배치·예산 정책 아래 의미 기반 후보 제외의 효과를 별도 비교한다. 예산으로 미검토된 단위는 그대로 보고한다.
5. **문맥·보류 비교:** 모호 사례가 실제로 남을 때만 제한된 문맥과 한 번의 확장을 비교한다. 같은 초기 상태에서 확장 효과를 측정한다.

기존 실험 V0–V4의 정의와 결과를 이 새 경로로 덮어쓰지 않는다. 새 실험에는 별도 버전 이름과 manifest를 사용한다. 대조군과 출력 schema가 다르면 공통의 목표 추출·보존 지표만 직접 비교하고, 추가 축이나 schema 실패는 별도 성능으로 보고한다. 표현·안전 검사에서 실패한 출력을 성공한 목표 추출로 세지 않는다.

조정셋에서 선택된 후보 하나만 대조군과 잠긴 평가셋에서 비교한다. 증거 판정과 리뷰 효용은 title/body 역할 실험의 점수에서 추정하지 않고, 필요한 Issue·revision·코드/검사 증거가 있는 별도 평가로 진행한다.

### 5.2 단계별 판단

| 단계 | 진행 조건 | 중단·보류 조건 |
|---|---|---|
| 라벨·단위 | 기준을 적용할 수 있고, 불일치 원인과 모호 영역을 설명할 수 있음 | 사람도 목표 정의를 다르게 적용함; 모델 수정 전에 정의를 다시 정리 |
| 오프라인 계약 | 원문 연결·조건·중복·미검토·권한 경계 시험 통과 | 새 목표 발명, 출처 권한 변화, 미검토를 성공으로 처리 |
| 조정 비교 | 목표 보존 개선과 잡음·비용의 교환관계가 설명됨 | 특정 PR·제목·표현 예외를 추가해야만 좋아짐 |
| 미사용 비교 | 사전 지정한 최소 유용 효과·비열화·비용 기준을 새 그룹에서도 충족 | 효과가 사라짐, 불확실성 구간이 허용 악화를 배제하지 못함, 특정 그룹에 큰 피해 |
| 증거·효용 | 근거가 맞는 판단과 실제 리뷰 결과가 개선되거나 사전 허용 범위 내 유지 | 거짓 완료·불필요한 요구가 증가, 빠르지만 더 부정확, 효과 미측정 |

“통계적으로 유의한 악화가 나오지 않았다”는 비열화 입증이 아니다. 허용 가능한 악화 폭과 최소 유용 효과는 실행 전에 정하고, 자료가 부족하면 채택을 보류한다. 현재처럼 작은 표본에서는 전체 평균의 소수점보다 어느 그룹·목표에서 실패했는지가 더 중요하다.

별도 차단 조건은 출처 권한 상승, wrong-source/wrong-revision 연결, privacy 유출, LLM 분류만으로의 `met` 생성이다. 시험에서 한 건이라도 발견되면 해당 후보의 제품 연결을 차단한다. 관측 0건이라고 실제 위험이 0이라는 뜻은 아니다. 일반 분류 오류와 이런 안전 경계를 하나의 평균 점수로 상쇄하지 않는다.

## 6. 대안과 지금 보류할 작업

| 대안 | 장점 | 지금의 판단 |
|---|---|---|
| 기존 규칙 중심 구조 유지 | 변경·비용이 작고 이미 동작하는 증거 검증을 보존 | 반드시 대조군으로 유지. 새 평가에서 이익이 없으면 그대로 유지 |
| 목표·주장 분리와 출처 연결을 추가한 제한적 후보 | 확인된 표현 문제를 직접 다루며 원문/권한 경계를 보존 | 우선 시험할 추천안. 세부 분할·문맥은 별도 증분으로 검증 |
| 소형 지도학습 분류기 | 안정된 라벨이 쌓이면 반복 분류 비용을 줄일 가능성 | 현재는 AI 라벨 편향과 표본 부족을 학습할 위험. 사람 라벨·비용 병목 확인 뒤 재검토 |
| 더 큰 모델·여러 AI 심사자 합의 | 어려운 판단의 보조 의견을 얻을 수 있음 | 기준·분모·출처 문제를 고치지 못함. 합의를 인간 정답이나 증명으로 사용하지 않음 |
| 전면 LLM화·전체 diff 투입 | 한 호출에서 풍부한 정보를 처리할 수 있음 | 목표를 구현에서 역추론할 위험과 비용. 이번 원인 해결의 첫 조치로 추천하지 않음 |

지금 필요한 것은 새로운 범용 리뷰 시스템이나 거대한 의미 그래프가 아니다. **동일 목표를 일관되게 세고, 목표와 주장을 함께 보존하며, 결론을 적합한 증거에만 연결하는 최소 변경의 효과를 공정하게 측정하는 것**이다. 성능 채택은 그 결과 뒤에 결정한다.
