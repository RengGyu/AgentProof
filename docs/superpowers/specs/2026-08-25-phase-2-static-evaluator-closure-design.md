## 1. Goal

Complete the two deterministic static evaluators already present:
documentation literal and path-change absence. Make their collection,
evaluation, validation, persistence, and rendering semantics identical.

This phase does not add test-case, workflow, return-value, UI, or browser
capability.

## 2. Documentation literal evaluator

Contract-declared document paths are fetched at the exact analyzed head.
Unchanged files are valid criterion evidence; changed-file membership is not a
requirement.

Required behavior:

- create a bounded evidence-index item for each successfully fetched declared
  path without retaining raw content in the report;
- compare normalized exact-head blob content to the approved literal;
- missing blob, head mismatch, permission failure, overflow, or incomplete
  collection -> `unavailable`;
- all declared paths contain the literal -> `satisfied`;
- collection is complete but a literal is absent -> `violated`; and
- evidence references resolve to the exact declared paths and analyzed head.

Collection retains the current closed limits: at most 8 declared artifact
paths and at most 64 KiB UTF-8 content per path. One evidence-index item is
created per successfully fetched path and remains within the existing 200-item
report evidence cap. Add `artifact` as a v2 evidence kind rather than labelling
an unchanged exact-head blob as a changed file. The report item contains only
ID, kind, bounded neutral label/summary, path locator, and confidence; content
stays in transient `verificationCriterionEvidenceV2.artifactBlobs`.

## 3. Path-change absence evaluator

GitHub collection must preserve both `filename` and `previous_filename` for
renamed files. The transient inventory contains normalized current and prior
paths.

Required behavior:

- complete current/prior inventory with no prohibited match -> `satisfied`;
- prohibited current or previous path -> `violated`;
- pagination cap, head drift, missing prior-name data for a rename, permission
  failure, or pasted/live mixed provenance -> `unavailable`;
- an absence result may legitimately have no positive evidence ref; full
  validation recomputes it from the transient complete inventory; and
- after full validation, report authenticity binds that result before the
  privacy-safe tenant projection is stored.

Do not invent a fake positive file reference or generic receipt merely to make
absence resemble presence evidence.

## 4. Runtime and persistence alignment

`generated_private_full` is the only boundary that may establish a new
satisfied static result. It requires raw transient evaluation context.

Reuse the existing lifecycle; do not invent a second signed payload:

```text
generateVerificationReportV2FromInput(PullRequestInput)
  -> validateRuntimeReportBoundary(generated_private_full, original input)
  -> createVerifiedAuthenticity(validated full report)
  -> prepareTenantDetailReportForStorage
  -> projectTenantPersistedReport
  -> validateTenantPersistedReport on read
```

The full-report `ReportAuthenticity` HMAC binds the canonical report including
schema/engine version, contract state, objective/criterion/result order,
requirement outcomes, and evidence references. The tenant persisted HMAC binds
the reduced contract projection. Only the server signing path can perform this
transition; API callers cannot supply signing authority or transient context.

Tenant storage may preserve the already validated result only when:

- the full report passed v2 validation;
- the projection is generated by the trusted server path;
- the signed/HMAC-bound persisted contract matches objective, criterion, state,
  and head/source policy; and
- raw artifact content and inventory are omitted.

Tenant validation must not reject a legitimate satisfied absence solely
because `evidenceRefs` is empty. It must also never recompute a new result from
the reduced projection.

## 6. RED acceptance matrix

### Documentation

1. Unchanged exact-head document containing the literal -> `satisfied`.
2. Complete exact-head document missing the literal -> `violated`.
3. Changed-file patch contains the literal but exact-head blob does not ->
   `violated`.
4. Blob permission failure or head mismatch -> `unavailable`.
5. Forged document evidence ref -> `v2_full` invalid.

### Absence

1. Complete inventory with no prohibited path -> `satisfied` with zero fake
   evidence refs.
2. Prohibited current path -> `violated`.
3. Prohibited `previous_filename` renamed away -> `violated`.
4. Missing previous name for a rename -> `unavailable`.
5. Partial pagination or pasted override -> `unavailable`.
6. Full validated satisfied absence survives tenant save/read with the same
   state.

### Privacy

Public, tenant, saved summary, Markdown, Slack, GitHub comment, and audit export
contain no raw document content, full inventory, previous-path inventory,
source binding, or private validation context.

## 7. Completion gate

Both static evaluators must pass direct, runtime-boundary, persistence,
projection, and endpoint replay tests. They may be enabled independently; a
failure in one evaluator does not authorize fallback to the other or to
heuristics.

## 8. Stop and rollback

Stop if collection completeness cannot distinguish renamed/partial inputs, or
if tenant persistence requires storing raw input. Rollback disables the
affected static evaluator's positive result while preserving observations and
the completed Phase 0/1 backbone.
